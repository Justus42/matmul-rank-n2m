### Was das Paper sagt (Yang v3, Abschnitt 1, wörtlich)

- Definition: „An R-rank decomposition of the ⟨k, l, m⟩ matrix multiplication tensor is a list of linear maps α_r : F^{k×l} → F, β_r : F^{l×m} → F and matrices C_r ∈ F^{k×m} for 0 ≤ r < R such that for all A ∈ F^{k×l} and B ∈ F^{l×m}, AB = Σ_r α_r(A) β_r(B) C_r. The rank of ⟨k, l, m⟩, denoted as R(⟨k, l, m⟩), is the smallest possible R such that a decomposition exists for ⟨k, l, m⟩.“
- „Theorem 2. For m ≥ n ≥ 4, R(⟨n, 2, m⟩) ≥ (n + 2)m + (n − 3).“
- Gültigkeit laut Abstract: „over arbitrary fields“.
- „Additionally, Theorem 2 proves R(⟨4, 2, 4⟩) ≥ 25 and R(⟨4, 2, 5⟩) ≥ 31“.

### Was der Lean-Code sagt (main, Commit 502fb1a)

```lean
structure BilinearAlgorithm (K : Type u) [Field K] (n l m r : ℕ) where
  alpha : Fin r → (Matrix (Fin n) (Fin l) K →ₗ[K] K)
  beta : Fin r → (Matrix (Fin l) (Fin m) K →ₗ[K] K)
  coeff : Fin r → Matrix (Fin n) (Fin m) K
  correct : ∀ (A : Matrix (Fin n) (Fin l) K) (B : Matrix (Fin l) (Fin m) K),
    A * B = ∑ k : Fin r, (alpha k A * beta k B) • coeff k

noncomputable def tensorRank (K : Type u) [Field K] (n l m : ℕ) : ℕ := by
  classical
  exact Nat.find (exists_bilinearAlgorithm K n l m)

theorem yang_theorem_two (K : Type u) [Field K] (n m : ℕ) (hn : 4 ≤ n) (hnm : n ≤ m) :
    (n + 2) * m + (n - 3) ≤ tensorRank K n 2 m

theorem rank_four_two_four_ge (K : Type u) [Field K] : 25 ≤ tensorRank K 4 2 4
```

`exists_bilinearAlgorithm K n l m : ∃ r, Nonempty (BilinearAlgorithm K n l m r)` wird durch `standardAlgorithm` belegt, den Schulalgorithmus mit einem Produkt `A i k * B k j` je Tripel.

### Abgleich Punkt für Punkt

1. **Format.** In `BilinearAlgorithm K n 2 m r` ist A eine `Fin n × Fin 2`-Matrix und B eine `Fin 2 × Fin m`-Matrix, das Ergebnis `Fin n × Fin m`. Das ist n×2 mal 2×m, also ⟨n,2,m⟩ in Yangs Schreibweise ⟨k,l,m⟩ = (k×l)·(l×m), nicht vertauscht. Entfaltet in mathlib (`Mathlib/Data/Matrix/Mul.lean`, c44e0c8): `A * B` ist die Instanz `HMul (Matrix l m α) (Matrix m n α) (Matrix l n α)` mit `hMul M N := fun i k => (fun j => M i j) ⬝ᵥ fun j => N j k`, und `dotProduct v w = ∑ i, v i * w i`. Das ist das gewöhnliche Matrixprodukt (AB)_{ik} = Σ_j A_{ij} B_{jk}. `•` auf Matrizen ist `Matrix.smul := Pi.instSMul` (`Mathlib/Data/Matrix/Defs.lean`), also Skalar mal jeden Eintrag. `alpha k A * beta k B` ist das Produkt zweier Elemente von K. `∑ k : Fin r` ist die Summe über genau r Indizes 0 ≤ k < r. `→ₗ[K]` sind K-lineare Abbildungen auf dem Matrixraum mit der punktweisen Modulstruktur. Das ist wörtlich Yangs Definition. **Stimmt.**
2. **Körper.** `(K : Type u) [Field K]` mit Universumsvariable u: jeder Körper in jedem Universum. `Field` ist in mathlib kommutativ, wie Yangs F. Keine weiteren Klassen- oder Hypothesenargumente (keine Charakteristik, nicht unendlich, nicht algebraisch abgeschlossen, keine Entscheidbarkeit). Dass Yangs Beweis intern zum algebraischen Abschluss übergeht, betrifft nur den Beweis, nicht die Aussage. **Stimmt.**
3. **Rangbegriff.** `tensorRank` ist `Nat.find` zur Existenzaussage „es gibt einen Algorithmus der Länge r“. Nach `Mathlib/Data/Nat/Find.lean` ist `Nat.find` das kleinste r mit dieser Eigenschaft (`Nat.find_spec`, `Nat.find_min'`). Die Existenz ist echt belegt (Schulalgorithmus, dessen `correct` bewiesen sein muss, sonst baut die Datei nicht). Es gibt keinen Ersatzwert. `classical` liefert nur die Entscheidbarkeitsinstanz, der Wert von `Nat.find` hängt davon nicht ab. Länge 0 und Nullsummanden sind zugelassen, wie im Paper (R ist nur eine Länge). Eine untere Schranke für `tensorRank` ist damit gleichwertig zu einer unteren Schranke für die Länge jedes Algorithmus (in `Basic.lean` auch als `le_tensorRank_iff` festgehalten). **Stimmt.**
4. **Zahl.** `(n + 2) * m + (n - 3) ≤ tensorRank K n 2 m` unter `4 ≤ n` und `n ≤ m` ist „für m ≥ n ≥ 4 gilt R ≥ (n+2)m + (n−3)“. Die Hypothesen sind genau die des Papers, weder stärker noch schwächer. Die abgeschnittene Subtraktion in ℕ schneidet nicht ab: aus n ≥ 4 folgt n − 3 ≥ 1, also stimmt `n - 3` in ℕ mit der ganzzahligen Differenz überein. Die Klammerung `(n + 2) * m + (n - 3)` ist (n+2)·m + (n−3). **Stimmt.**
5. **B-007.** `rank_four_two_four_ge (K : Type u) [Field K] : 25 ≤ tensorRank K 4 2 4` ist R_K(⟨4,2,4⟩) ≥ 25 für jeden Körper. Rechnung: (4+2)·4 + (4−3) = 24 + 1 = 25, und n = m = 4 erfüllt 4 ≤ n ≤ m. Die Aussage ist nicht durch eine andere Lean-Tatsache trivial oder widersprüchlich: `tensorRank_le_mul` gibt ≤ 4·2·4 = 32, die Hopcroft-Kerr-Schranke wäre 26. **Stimmt.**
6. **Nebenwirkungen in den Importen.** `Statements.lean` importiert `Basic`, `CeilBound`, `YangN3`, `Upper3x2x6` und mathlib. In diesen Dateien und in `YangN3Teil1` bis `YangN3Teil3` gibt es keine Zeile mit `instance`, `notation`, `infix`, `macro`, `syntax`, `axiom`, `attribute`, `set_option`, `implemented_by`, `opaque` oder `unsafe` (per `grep`). Vorhanden sind nur `open Matrix`, `open Module`, `open Classical in` vor einzelnen Definitionen und `@[simp]` an lokalen Hilfssätzen. Keine Datei definiert `YangBounds.tensorRank` oder `YangBounds.BilinearAlgorithm` neu.
